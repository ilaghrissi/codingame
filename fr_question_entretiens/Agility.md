# Agility

**Q1** Tu connais quoi comme cérémonies agile?

**R1**

✅ Les 5 cérémonies Scrum (officielles)
1. **Sprint Planning** (Planification du Sprint)
   - Quand : Début de chaque sprint 
   - Qui : PO, Scrum Master, équipe de dev 
   - But : Décider quoi faire dans le sprint (objectifs) et comment le faire (tâches).

2. **Daily Scrum** (Stand-up quotidien)
   - Quand : Tous les jours (15 min)
   - Qui : Équipe de dev (Scrum Master souvent présent)
   - But : Synchronisation rapide :
     - Ce que j’ai fait hier 
     - Ce que je vais faire aujourd’hui 
     - Obstacles éventuels

3. **Sprint Review** (Revue de Sprint)
   - Quand : Fin de sprint 
   - Qui : PO, dev, stakeholders 
   - But : Présenter le travail terminé (livrable), récupérer du feedback

4. **Sprint Retrospective** (Rétrospective)
   - Quand : Juste après la Sprint Review 
   - Qui : Toute l’équipe 
   - But : Identifier ce qui a bien fonctionné, mal fonctionné et comment s'améliorer au prochain sprint

5. **Le Sprint lui-même** (parfois considéré comme une "cérémonie")
   - Période fixe (ex : 2 semaines) où l’équipe travaille pour livrer un incrément de produit terminé.

🔁 Autres cérémonies ou pratiques en Agile (hors Scrum strict)
- Backlog Refinement / Grooming 
  - Objectif : Préparer les user stories pour les futurs sprints (ajout, découpage, estimation). 
  - Pas une cérémonie officielle, mais très courante et utile.

- Démo 
  - Peut être intégrée à la Sprint Review ou faite à part pour les parties prenantes externes.

**Q1.** On fait quoi en Rétro? est-ce que tu peux me dire une proposition que t’as donné
lors de votre dernière rétrospective ?

**R1**
En rétrospective (ou Sprint Retrospective), l’équipe Scrum prend un moment à la fin du sprint pour réfléchir à comment s’est déroulé le travail, avec pour objectif de s’améliorer en continu.

- Réduire les réunions inutiles ou trop longues. 
- Mieux définir les user stories avant de les inclure dans le sprint. 
- Ajouter plus de tests automatiques. 
- Faire un point quotidien de 5 min après le Daily pour régler les blocages techniques.


**Q1** Y a une cérémonie très importante, elle s’appelle l’affinage, tu sais de quoi je parle?

**R1**

Oui, absolument, tu fais référence à la cérémonie d’affinage (ou Backlog Refinement, parfois appelée aussi grooming).

🔍 Qu’est-ce que l’affinage (Backlog Refinement) ?
L’affinage est une réunion Scrum non officielle mais essentielle, pendant laquelle :
- L’équipe produit (Product Owner, Scrum Master, développeurs, parfois testeurs et UX) se réunit pour préparer les futures user stories.
- On clarifie, découpe, affine et priorise les éléments du Product Backlog

🎯 Objectifs de l’affinage :
1. Clarifier les stories avec le Product Owner. 
2. Découper les stories trop grosses (épiques). 
3. Estimer les tâches (souvent avec du Planning Poker). 
4. Vérifier que les stories sont prêtes pour être prises dans le prochain sprint (prêtes = critères d'acceptation clairs, testabilité, compréhension, taille raisonnable).


🧠 Pourquoi c’est important ?
- Ça permet de gagner du temps pendant le sprint planning. 
- Ça garantit que les développeurs comprennent bien ce qu’ils vont développer. 
- Ça évite de travailler dans le flou. 
- Le PO peut aussi réadapter les priorités en fonction des retours.

**Q1.** C’est quoi SAFe ?

**R1**

SAFe est un cadre (framework) agile à l’échelle de l’entreprise. Il permet de déployer l’agilité non pas juste au niveau d’une équipe (comme Scrum), mais sur des dizaines voire des centaines d'équipes qui travaillent ensemble sur des produits complexes.


**Q1** C’est quoi un Agile Release Train (ART) ?

**R1**

Un Agile Release Train (ou simplement train agile) est une grosse équipe composée de plusieurs équipes agiles (entre 50 et 125 personnes, typiquement 5 à 12 équipes Scrum).

📌 Pourquoi on l’appelle "train" ?
Parce que toutes les équipes embarquées dans ce "train" avancent à la même vitesse, sur une même cadence de livraison.
👉 Le train part à l’heure (ex. tous les 3 mois) et tout le monde doit être prêt.
